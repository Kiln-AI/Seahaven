# `/schema` and `/state` always use the base `State` model, dropping every field an environment's State subclass declares

## Summary

`HTTPEnvServer` threads the environment's own `Action` and `Observation` classes through to the HTTP surface, but never its `State` subclass. Two endpoints are wrong as a result:

- `GET /schema` returns `state` as the JSON Schema of the base `openenv.core.env_server.types.State`, so every environment publishes a state schema of just `episode_id` and `step_count`, regardless of what its `State` subclass declares.
- `GET /state` is registered with `response_model=State`, so FastAPI serialises the live state through the base model and strips every subclass field from the response body.

`create_app()` has no `state_cls` parameter, so an environment author cannot supply the right class even deliberately.

This affects every environment that subclasses `State` — 28 of the environments in this repo do (`ChessState`, `GitState`, `AtariState`, `MazeState`, `JupyterState`, …).

The WebSocket `state` frame is **not** affected: it calls `state.model_dump()` on the live session env (`http_server.py:1607`) and preserves subclass fields. So the two transports currently disagree about the same state object.

## Reproduction

```python
# app.py
from typing import List

from pydantic import Field

from openenv.core.env_server.http_server import create_app
from openenv.core.env_server.interfaces import Environment
from openenv.core.env_server.types import Action, Observation, State


class EchoAction(Action):
    message: str = ""


class EchoObservation(Observation):
    response: str = ""


class EchoState(State):
    counter: int = 0
    history: List[str] = Field(default_factory=list)


class EchoEnv(Environment):
    def __init__(self):
        super().__init__()
        self._state = EchoState(episode_id="ep-1", step_count=3, counter=42, history=["a", "b"])

    @property
    def state(self) -> EchoState:
        return self._state

    def reset(self) -> EchoObservation:
        return EchoObservation(response="")

    def step(self, action: EchoAction) -> EchoObservation:
        self._state.counter += 1
        return EchoObservation(response=action.message)


app = create_app(EchoEnv, EchoAction, EchoObservation, env_name="echo_env")
```

```
uvicorn app:app --port 8000
```

### Actual

```
$ curl -s localhost:8000/schema | jq '.state.properties | keys'
[
  "episode_id",
  "step_count"
]

$ curl -s localhost:8000/state
{"episode_id":"ep-1","step_count":3}
```

### Expected

```
$ curl -s localhost:8000/schema | jq '.state.properties | keys'
[
  "counter",
  "episode_id",
  "history",
  "step_count"
]

$ curl -s localhost:8000/state
{"episode_id":"ep-1","step_count":3,"counter":42,"history":["a","b"]}
```

`counter` and `history` are declared fields of `EchoState`. `EchoState(...).model_dump()` returns them, and so does the WebSocket `state` frame.

## Cause

All references are to `src/openenv/core/env_server/http_server.py`. The line numbers hold for both the **0.4.2** release and current **`main`** (`da59295`, `version = "0.4.3.dev0"`) — the file is byte-identical between the two, so this is not fixed on `main`.

- **`http_server.py:1451`** — in `get_schemas()`, `state` is hardcoded to the base class while the other two fields use the environment's classes:

  ```python
  return SchemaResponse(
      action=self.action_cls.model_json_schema(),
      observation=self.observation_cls.model_json_schema(),
      state=State.model_json_schema(),
  )
  ```

- **`http_server.py:1392`** — the `/state` route is registered with `response_model=State`. Its own description at `http_server.py:1398` reads "The structure of the state object is defined by the environment's State model", which the annotation contradicts.

- **`http_server.py:1699`** — `create_app()` accepts `action_cls` and `observation_cls` but no `state_cls`. The same omission runs through the whole chain: `create_fastapi_app()` (`http_server.py:1790`), `create_web_interface_app()` (`web_interface.py:425`), and `HTTPEnvServer.__init__` (`http_server.py:173`, which stores `self.action_cls` / `self.observation_cls` at `http_server.py:242-243`).

Two notes:

- The base `State` sets `extra="allow"` (`types.py:187`), but that does not rescue the response. FastAPI validates the handler's return value against the declared `response_model`, and a field *declared* on a subclass is not an extra on the base, so it is dropped.
- The framework already models a per-environment state type: `Environment` is `Generic[ActT, ObsT, StateT]` with `StateT = TypeVar("StateT", bound=State)` (`interfaces.py:16`, `interfaces.py:213`) and `state` is an abstract property returning `StateT` (`interfaces.py:307-310`). The HTTP server just never consumes it.

## Suggested fix

Thread the state class the same way the action and observation classes already are:

1. Add `state_cls: Type[State] = State` to `create_app()`, `create_fastapi_app()`, `create_web_interface_app()`, and `HTTPEnvServer.__init__` (storing it as `self.state_cls`).
2. In `get_schemas()`, use `state=self.state_cls.model_json_schema()`.
3. Register the `/state` route with `response_model=self.state_cls`.

Defaulting `state_cls` to `State` keeps existing environments working unchanged; an environment that declares a `State` subclass opts in by passing it.
