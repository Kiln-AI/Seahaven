Deprecate HTTP `/reset`, `/step`, `/state`

## Summary

These endpoints have been effectively broken for a while (context below), but they are still registered, still in the OpenAPI schema, and still documented as the episode loop. They don't error — they return plausible-looking responses that are silently meaningless, which is the worst way for an endpoint to be broken. Anyone who reaches for HTTP instead of the WebSocket transport gets wrong data and no signal that anything is wrong.

Please either deprecate them with a clear error, or remove them.

## What's wrong

`HTTPEnvServer`'s `reset_handler`, `step_handler` and `get_state_handler` each build a brand-new `Environment` via `self._env_factory()` and close it in a `finally` block before returning. Every HTTP request runs against its own throwaway instance: `/reset` resets one, `/step` steps a different one, `/state` reads a third. None of them observe each other, so the three routes cannot represent an episode.

Current `main` (`da59295`, `0.4.3.dev0`), `src/openenv/core/env_server/http_server.py` — byte-identical to the released `0.4.2`, so this affects the current release:

- `reset_handler` — builds at line 674, closes at 695
- `step_handler` — builds at line 709, closes at 733
- `get_state_handler` — builds at line 1347, closes at 1351

## Reproduction

Running `envs/grid_world_env/server/app.py` and driving the episode over HTTP:

```bash
curl -s -X POST http://localhost:8000/reset
# {"observation":{"x":0,"y":0,"message":"Welcome to Grid World! Goal is at [4, 4]."},...}

curl -s -X POST http://localhost:8000/step -H "Content-Type: application/json" -d '{"action": {"action": "DOWN"}}'
# {"observation":{"x":1,"y":0,"message":"Keep going..."},...}

curl -s -X POST http://localhost:8000/step -H "Content-Type: application/json" -d '{"action": {"action": "DOWN"}}'
# {"observation":{"x":1,"y":0,"message":"Keep going..."},...}     <-- agent never moved

curl -s http://localhost:8000/state
# {"episode_id":"c1977bfa-d32f-4e31-84e1-fb6d32e5686c","step_count":0}   <-- after two steps
```

The second `DOWN` returns the same position as the first, because it ran against a fresh environment starting at `[0, 0]` again. `/state` reports `step_count: 0` after both.

`envs/grid_world_env/server/app.py` still carries the fossil of when this worked:

```python
# Create single environment instance
# This is reused for all HTTP requests.
# env = GridWorldEnvironment()
```

## How it happened

It's a regression, not a design choice. The handlers held one environment per process for two months:

| Commit | Date | Effect on the HTTP handlers |
|---|---|---|
| [`274b0de`](https://github.com/huggingface/OpenEnv/commit/274b0de) | 2025-10-08 | "add http server wrapper for gymnasium APIs" — `self.env = env`; handlers call `self.env.reset()` / `self.env.step()`. Stateful. |
| [`85c47c6`](https://github.com/huggingface/OpenEnv/commit/85c47c6) | 2025-12-04 | Adds WebSocket support. HTTP handlers still use `self.env`. Still stateful. |
| [`438f966`](https://github.com/huggingface/OpenEnv/commit/438f966) | 2025-12-10 | Makes the env factory mandatory, still keeps `self.env = env()`. Still stateful. |
| [`86a222d`](https://github.com/huggingface/OpenEnv/commit/86a222d) | 2025-12-12 | **The regression.** Deletes `self.env = env()` and rewrites every handler to build and close a throwaway `_env`. |
| [`402d144`](https://github.com/huggingface/OpenEnv/commit/402d144) | 2025-12-15 | Deletes `src/openenv/core/http_env_client.py` — the last HTTP-transport client. |

`86a222d`'s commit message is entirely about generics (`ActT`/`ObsT`/`StateT`) and async-method detection; it doesn't mention episode semantics. `self.env` had been used partly for `hasattr(self.env, "reset_async")` probing at construction time, and when that moved to per-call checks on a locally-built `_env`, the handlers that depended on `self.env` for *state* were left building throwaways. Three days later the HTTP client was deleted, so nothing first-party exercised these routes anymore and nothing caught it.

## A previous attempt at this

[#252 "[PATCH] Deprecate HTTP in websockets"](https://github.com/huggingface/OpenEnv/pull/252) tried to deprecate HTTP and was abandoned — it removed the HTTP *client* library and broke on import, because a dozen environment clients still imported `HTTPEnvClient`.

This request is narrower and shouldn't hit that wall: it's about the three server-side routes, which no first-party client has used since `402d144`.

## Why nothing catches it today

- `envs/grid_world_env/test_grid_world.sh` posts `/reset`, posts one `/step`, then greps `/state` for the literal string `"step_count"`. A fresh env's `step_count: 0` contains that substring, so it passes either way.
- The CLI's `mode_endpoint_consistency` criterion (`src/openenv/cli/_validation.py`, around lines 379-404) only checks that `/reset`, `/step` and `/state` appear in the OpenAPI `paths` — presence, never behaviour.

## Someone already worked around it

`envs/calendar_env/server/openenv_wrapper/custom_http_server.py` subclasses `HTTPEnvServer`, restores a persistent instance in `__init__`:

```python
# Create a persistent environment instance for HTTP endpoints
# The parent class stores env_factory in self._env_factory
# We create one instance for the HTTP endpoints (not WebSocket)
if callable(self._env_factory):
    self.env = self._env_factory()
else:
    self.env = self._env_factory
```

and then fully overrides `register_routes` to reimplement `/reset`, `/step` and `/state` against it — hand-restoring exactly what `86a222d` removed.

## The docs disagree with each other

- `tutorial/02-deployment.md` (lines 44-54) labels `/reset` and `/step` "(stateless)" and says HTTP is "for debugging or stateless use cases".
- `docs/source/environments/grid_world.md:115` says "HTTP requests are stateless, so the environment instance must remember the agent's position between calls" — describing the pre-regression behaviour as current.
- `docs/source/guides/simulation-vs-production.md` still documents `/reset` / `/step` / `/state` as the simulation-mode episode loop, unqualified.

## Suggested action

**Preferred: make the routes fail loudly.** Have `/reset`, `/step` and `/state` return a clear error saying HTTP episode control is deprecated, that the endpoint cannot hold an episode because a fresh environment is built per request, and that `/ws` is the supported transport. Keeping the paths registered means the CLI's `mode_endpoint_consistency` check keeps passing while the behaviour stops lying.

**Alternative: remove them outright**, if per-request semantics aren't going to be supported at all.

Either way, `tutorial/02-deployment.md`, `docs/source/environments/grid_world.md` and `docs/source/guides/simulation-vs-production.md` need updating so they stop describing behaviour the code doesn't have — and `envs/calendar_env`'s workaround is worth revisiting once the base class's intent is settled.
